By eye, the early part of the reference curves looks similar: the basic achievements (collect_wood, place_table, collect_sapling, place_plant) saturate first, wake_up starts near 100% and declines later, and the wood/stone tool chain follows. In the reference runs PPO-RNN only pulls ahead after hundreds of millions of steps. At 3M steps the difference between the two is within single-seed noise.

Not tested here

The end-of-training numbers (PPO return about 26–28, PPO-RNN about 37) need the full 1e9 steps: about 3–4 hours per run on one GPU (the reference runs) versus about 10 days on this CPU. To finish the test on a GPU:

pip install -e ".[jax]" && pip install -U "jax[cuda12]"
python train_craftax.py output_dir=runs/ppo seed=0
python train_craftax.py algo.rnn=true output_dir=runs/ppo_rnn seed=0
python compare_craftax_run.py runs/ppo/metrics.jsonl --ref ppo
python compare_craftax_run.py runs/ppo_rnn/metrics.jsonl --ref ppo_rnn

A run is reproduced when compare_craftax_run.py reports the return, length, achievements per episode and per-achievement rates inside the reference ranges. The ranges are read off chart images and are approximate, so use 2–3 seeds. If a run is interrupted, re-run the same command to resume.

!
Hyper-parameters follow the Craftax PPO baselines (1024 envs, 64 steps, lr 2e-4, γ 0.99, λ 0.8, 3×512 tanh MLP / GRU-512). The reference runs' own config was not available, so confirm these against it if possible.
