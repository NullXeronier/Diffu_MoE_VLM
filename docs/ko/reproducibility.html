확인 항목결과
단위 테스트: NumPy 기준 대비 GAE, running moments, optimistic reset(끝난 환경에 서로 다른 새 월드), MoE 균형 손실, 에피소드 경계에서 GRU 상태 초기화통과 (tests/test_jax_rl.py)
결정론: 같은 시드는 비트 단위로 같은 지표(PPO, PPO-RNN), 다른 시드는 다른 지표통과
재개: 2업데이트 + 저장/복원 + 2업데이트가 연속 4업데이트와 비트 단위로 동일(지표, 파라미터)통과
실제 규모 결정론: 기본 설정(환경 1024 × 64스텝), 한 번의 scan과 5업데이트 청크 + 체크포인트를 프로세스를 바꿔 이어 붙인 런 비교, 업데이트 5–30의 기록 값 390개차이 0개
학습, PPO, 100업데이트 = 655만 스텝 (레퍼런스 예산의 0.66%)리턴 1.49 → 6.66, 에피소드당 업적 2.4 → 7.6
학습, PPO-RNN, 50업데이트 = 328만 스텝리턴 1.49 → 5.15 (같은 스텝의 PPO: 5.47)

이 CPU의 처리량은 초당 약 1,150–1,250 환경 스텝이다(레퍼런스 GPU 런: 5만–9.5만).

레퍼런스 곡선의 시작과 일치한다. 기본 업적(collect_wood, place_table, collect_sapling, place_plant)이 먼저 포화되고, wake_up은 100% 근처에서 시작해 나중에 떨어지며, 나무·돌 도구 순서가 뒤따른다. 레퍼런스에서 PPO-RNN이 앞서는 것은 수억 스텝에 걸쳐 나타나고, 300만 스텝에서는 두 모델 차이가 시드 1개의 노이즈 범위 안이다.

여기서 테스트하지 않은 것

학습 종료 시점 수치(PPO 리턴 약 26–28, PPO-RNN 약 37)는 10억 스텝 전체가 필요하다. GPU 1대로 런당 약 3–4시간(레퍼런스 런)이고, 이 CPU로는 약 10일이다. GPU에서 테스트를 마치려면:

pip install -e ".[jax]" && pip install -U "jax[cuda12]"
python train_craftax.py output_dir=runs/ppo seed=0
python train_craftax.py algo.rnn=true output_dir=runs/ppo_rnn seed=0
python compare_craftax_run.py runs/ppo/metrics.jsonl --ref ppo
python compare_craftax_run.py runs/ppo_rnn/metrics.jsonl --ref ppo_rnn

compare_craftax_run.py가 리턴, 길이, 에피소드당 업적, 업적별 성공률이 레퍼런스 범위 안에 있다고 보고하면 재현된 것이다. 범위는 차트 이미지에서 읽은 근사치이므로 시드 2–3개를 쓴다. 런이 중단되면 같은 명령을 다시 실행하면 이어서 학습한다.

!
하이퍼파라미터는 Craftax PPO baseline을 따른다(환경 1024개, 64스텝, lr 2e-4, γ 0.99, λ 0.8, 3×512 tanh MLP / GRU-512). 레퍼런스 런 자체의 설정은 구하지 못했으므로, 가능하면 그것과 대조해 확인해야 한다.
