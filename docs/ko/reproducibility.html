Craftax 재현성 테스트

레퍼런스 W&B 런(Craftax-Symbolic-v1-1000M, Craftax-Symbolic-v1-PPO_RNN-1000M, craftax_reference.json)을 train_craftax.py로 재현하는 것이 목표다.

!
범위: 레퍼런스 런은 아직 재현하지 못했다. 여기서 확인한 것은 CPU에서 학습이 결정론적이고 이어서 돌릴 수 있다는 점, 초기 학습 모양이 레퍼런스 곡선 앞부분과 비슷하다는 점까지다. 10억 스텝 비교는 아직이고, 레퍼런스 런의 설정을 구하지 못해 Craftax baseline 하이퍼파라미터로 돌릴 예정이다.

확인 항목결과
단위 테스트: GAE를 NumPy 구현과 대조, running moments, optimistic reset(끝난 환경마다 서로 다른 새 월드), MoE load-balancing loss, 에피소드가 바뀔 때 GRU 상태 초기화통과 (tests/test_jax_rl.py)
결정론(CPU): 시드가 같으면 지표가 비트 단위로 같고(PPO, PPO-RNN) 시드가 다르면 달라진다. GPU에서는 비트 단위로 같지 않을 수 있다통과
재개: 2업데이트 → 저장·복원 → 2업데이트가 4업데이트를 한 번에 돌린 것과 비트 단위로 같다(지표, 파라미터)통과
실제 규모 결정론: 기본 설정(환경 1024 × 64스텝)에서 scan 한 번으로 끝낸 런과, 5업데이트마다 체크포인트를 남기고 프로세스를 바꿔 이어 붙인 런을 비교. 업데이트 5–30에서 기록한 값 390개차이 0개
학습, PPO, 100업데이트 = 655만 스텝 (레퍼런스 예산의 0.66%)리턴 1.49 → 6.66, 에피소드당 업적 2.4 → 7.6
학습, PPO-RNN, 50업데이트 = 328만 스텝리턴 1.49 → 5.15 (같은 스텝의 PPO: 5.47)

이 CPU로는 초당 1,150–1,250 환경 스텝 정도가 나온다(레퍼런스 GPU 런은 5만–9.5만).

여기서 테스트하지 않은 것

학습이 끝났을 때의 수치(PPO 리턴 약 26–28, PPO-RNN 약 37)를 보려면 10억 스텝을 다 돌려야 한다. GPU 1대로는 런당 3–4시간(레퍼런스 런 기준), 이 CPU로는 열흘쯤 걸린다. GPU에서 마저 확인하려면 다음을 돌린다.

pip install -e ".[jax]" && pip install -U "jax[cuda12]"
python train_craftax.py output_dir=runs/ppo seed=0
python train_craftax.py algo.rnn=true output_dir=runs/ppo_rnn seed=0
python compare_craftax_run.py runs/ppo/metrics.jsonl --ref ppo
python compare_craftax_run.py runs/ppo_rnn/metrics.jsonl --ref ppo_rnn

compare_craftax_run.py가 리턴, 길이, 에피소드당 업적, 업적별 성공률이 모두 레퍼런스 범위 안이라고 하면 재현된 것으로 본다. 범위는 차트 이미지에서 읽은 근사치라 시드는 2–3개 쓴다. 런이 끊기면 같은 명령을 다시 치면 이어서 학습한다.

!
하이퍼파라미터는 Craftax PPO baseline을 따랐다(환경 1024개, 64스텝, lr 2e-4, γ 0.99, λ 0.8, 3×512 tanh MLP / GRU-512). 레퍼런스 런의 실제 설정은 구하지 못했다. 구할 수 있다면 그것과 맞춰 봐야 한다.
